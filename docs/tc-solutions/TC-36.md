# TC-36 — Suite de integración que detenga regresiones reales

## Objetivo

Construir una red de pruebas que detecte regresiones de ejecución reactiva, autorización, contratos HTTP, idempotencia y mensajería. Las pruebas críticas deben ejecutarse en un checkout nuevo con Docker y su omisión debe hacer fallar el control de CI.

## Problema encontrado

El proyecto ya tenía pruebas unitarias, pruebas con MongoDB de Testcontainers y una integración de RabbitMQ. Sin embargo, `DELETE /api/ingredients/{id}` sólo comprobaba que se llamara al método del repositorio. Esa aserción no detectaría un publisher de borrado construido y descartado. Las pruebas HTTP de seguridad usaban sobre todo MockMvc. Tampoco existía un pipeline que comprobara si las suites críticas se habían ejecutado, por lo que una prueba de contenedor omitida podía dejar un build verde.

## Solución implementada

La solución fue añadir un `TestPublisher` y un `PublisherProbe` al caso de eliminación. La prueba se suscribe a la respuesta y comprueba que no aparece `204` mientras el borrado está pendiente. Sólo después de completar el publisher admite la respuesta.

```java
TestPublisher<Void> deletion = TestPublisher.createCold();
PublisherProbe<Void> probe = PublisherProbe.of(deletion.mono());
Mockito.when(repo.delete(ingredient)).thenReturn(probe.mono());

StepVerifier.create(controller.deleteIngredient("FLTO"))
    .expectSubscription()
    .then(probe::assertWasSubscribed)
    .expectNoEvent(Duration.ofMillis(20))
    .then(deletion::complete)
    .expectNextMatches(response -> response.getStatusCodeValue() == 204)
    .verifyComplete();
```

`Tc36RuntimeContractTest` inicia MongoDB en Testcontainers y arranca la aplicación MVC en un puerto aleatorio. `WebTestClient` envía peticiones HTTP reales. Cada caso crea usuarios e ingredientes sintéticos y los elimina al terminar. Comprueba lectura pública, denegación de rutas ADMIN y no declaradas, escritura sin CSRF, escritura con CSRF válido y creación y borrado persistentes. El estado de Mongo se consulta de nuevo por HTTP, de modo que un publisher descartado no puede aparentar éxito.

Las pruebas existentes conservan las otras responsabilidades. `OrderIdempotencyMongoTest` cubre reintentos de una misma clave sin duplicar orden, reserva ni outbox. `OrderOutboxMongoTest` prueba fallo y recuperación del envío. `RabbitKitchenDeliveryTest` usa MongoDB y RabbitMQ en contenedores para comprobar redelivery, retry y DLQ. Los tests de reglas, pricing, workflow, serialización, registro, conversión de correo y seguridad siguen siendo rápidos en sus módulos.

El workflow ejecuta el reactor Maven completo con Docker disponible y después corre las pruebas Angular en Chrome Headless. `verify_tc36_reports.py` lee los XML de Surefire y falla si falta una suite o un caso crítico, si se omite o si aparece un fallo. Sólo admite las omisiones conocidas de tres clases Selenium heredadas.

## Flujo

Checkout -> comprobar Docker -> `mvn -U clean test` -> ejecutar unitarios, contratos, HTTP y contenedores -> probar Angular -> revisar XML de Surefire -> publicar reportes o fallar el pipeline.

## Archivos principales

- `IngredientControllerTest.java`: asegura suscripción y completion del borrado reactivo.
- `Tc36RuntimeContractTest.java` y `tacocloud/pom.xml`: añaden HTTP real con MongoDB en contenedor y sus dependencias de prueba.
- `verify_tc36_reports.py`: exige suites y casos críticos, incluidos los de MongoDB, RabbitMQ e idempotencia.
- `tc36-integration.yml`: ejecuta Maven en CI y conserva los reportes de Surefire.

## Pruebas

| Concepto | Test | Archivo |
|---|---|---|
| Publisher de DELETE | `shouldWaitForIngredientDeletePublisherBeforeNoContent` | `IngredientControllerTest.java` |
| HTTP y MongoDB reales | `publicCatalogUsesRealMvcAndContainerMongo`, `adminCreateAndDeleteChangeRealMongoState` | `Tc36RuntimeContractTest.java` |
| Autorización y CSRF | `userCannotReachAdminOrUndeclaredRoutes`, `csrfBlocksWriteWithoutTokenAndAllowsValidatedControllerCall` | `Tc36RuntimeContractTest.java` |
| Reintento idempotente | `sequentialRetryKeepsOneOrderReservationAndOutboxEvent` | `OrderIdempotencyMongoTest.java` |
| Outbox y broker | `shouldRetryBrokerFailureAfterRestartWithSameEventId`, `shouldConsumePublishedEventTwiceButChangeKitchenStateOnce`, `shouldDeadLetterExhaustedTransientFailure` | `OrderOutboxMongoTest.java`, `RabbitKitchenDeliveryTest.java` |
| Contratos | `postOrderAndApiProblemMatchDocumentedStatusAndSchema`, `shouldRemoveRawCardFieldsFromOrderDomain` | `OpenApiContractTest.java`, `PaymentSecurityContractTest.java` |

En la ejecución local aprobaron los casos nuevos, las integraciones de MongoDB y RabbitMQ y la regresión Maven. El verificador aceptó sólo las omisiones heredadas indicadas.

Desde la carpeta `tacocloud`, `mvn -U clean test` ejecuta el reactor completo. Para repetir un subconjunto se puede usar `mvn -U -pl tacocloud -am test -Dtest=Tc36RuntimeContractTest -Dsurefire.failIfNoSpecifiedTests=false` o cambiar el módulo y la clase por `tacocloud-kitchen` y `RabbitKitchenDeliveryTest`.
