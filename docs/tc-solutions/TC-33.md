# TC-33 — Reemplazar Notes por anuncios operativos seguros

## Objetivo

Convertir las notas temporales de Actuator en anuncios operativos identificables y persistentes. Un administrador debe poder crearlos, consultarlos y retirarlos sin que una petición normal exponga información interna.

## Problema encontrado

`NotesEndpoint` guardaba las notas en un `ArrayList` compartido. El índice de la lista servía como identificador y cambiaba al borrar otros elementos. Las notas se perdían al reiniciar, no caducaban y no tenían límites de texto ni cantidad. Tampoco separaban los datos guardados de los datos que debía recibir un cliente.

## Solución implementada

La solución fue sustituir ese endpoint por `/api/admin/announcements`. `OpsAnnouncement` se guarda en MongoDB con ID UUID, texto, severidad, fechas, autor y estado activo. La petición sólo acepta texto, severidad y expiración. `AnnouncementResponse` omite `createdBy` y el cupo interno. El repositorio no se exporta por Data REST, por lo que las escrituras pasan por la validación del servicio. La regla existente de `/api/admin/**` exige ADMIN y Spring Security sigue exigiendo CSRF para escribir.

El número máximo de anuncios activos se representa con cupos numerados. MongoDB impone que sólo un anuncio activo ocupe cada cupo. La restricción evita que dos altas concurrentes sobrepasen el límite, incluso si llegan a instancias distintas.

```java
@Indexed(name = "announcement_active_slot_unique", unique = true,
    partialFilter = "{ 'active': true }")
private int slot;

return mongo.insert(announcement)
    .onErrorResume(DuplicateKeyException.class,
        error -> insert(id, slot + 1, request, now, author));
```

Antes de crear o listar, el servicio elimina anuncios vencidos o desactivados. La consulta individual también exige que el anuncio esté activo y no haya vencido. DELETE busca por ID y cambia `active` a `false` de forma atómica, lo que libera el cupo correcto. Si el ID no corresponde a un anuncio vigente, responde 404.

```java
Query query = Query.query(Criteria.where("_id").is(id)
    .and("active").is(true)
    .and("expiresAt").gt(clock.instant()));
return mongo.findAndModify(query, Update.update("active", false),
    OpsAnnouncement.class)
    .switchIfEmpty(Mono.error(new ResponseStatusException(
        HttpStatus.NOT_FOUND, "Announcement not found")))
    .then();
```

`Clock` permite evaluar la caducidad sin depender de esperas en las pruebas. El servicio rechaza texto vacío, caracteres de control, severidad ausente y fechas inválidas. La configuración limita el texto, los anuncios activos y la vida máxima. Los valores iniciales son 500 caracteres, 20 anuncios y 168 horas.

## Flujo

ADMIN envía POST con CSRF -> validar contenido y fecha -> limpiar vencidos -> ocupar un cupo libre en MongoDB -> devolver respuesta sin autor. GET consulta sólo anuncios vigentes. DELETE desactiva por ID -> libera el cupo.

## Archivos principales

- `OpsAnnouncement.java` y `OpsAnnouncementRepository.java`: definen el documento persistente, el índice único y las consultas de anuncios vigentes.
- `AnnouncementService.java`: valida, limpia, asigna cupos y realiza el borrado lógico.
- `AnnouncementRequest.java`, `AnnouncementResponse.java` y `AnnouncementController.java`: delimitan el contrato HTTP administrativo.
- `application.yml`: configura los límites. Se retiró `NotesEndpoint.java` porque su almacenamiento en memoria ya no representa esta función.
