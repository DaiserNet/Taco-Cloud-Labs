# TC-03 — Creación validada de ingredientes

## Objetivo

Corregir `POST /api/ingredients` para validar el ingrediente recibido, persistirlo mediante una cadena reactiva y devolver `201 Created` con un encabezado `Location` construido a partir del ID realmente guardado.

## Problema encontrado

El endpoint recibía un `Mono<Ingredient>` como cuerpo y construía manualmente una URL fija con host, puerto y una ruta que no correspondía al endpoint actual. Esa forma dificultaba que Bean Validation actuara directamente sobre el objeto de entrada y hacía que la ubicación dependiera del entorno de desarrollo. También era importante que el encabezado usara el resultado de `save`, porque el repositorio puede asignar o normalizar el identificador durante la persistencia.

## Solución implementada

El método recibe `@Valid @RequestBody Ingredient`. Las restricciones reales del dominio —`@NotBlank` para `id` y `name`, y `@NotNull` para `type`— se evalúan antes de ejecutar el controlador. Si fallan, Spring responde `400` y el repositorio no recibe ninguna llamada.

Para conservar un flujo explícito, el objeto se incorpora con `Mono.just(ingredient)`. `flatMap(repo::save)` encadena la persistencia porque `save` devuelve `Mono<Ingredient>`. Después, `map` trabaja con la entidad emitida por el repositorio y construye la URI mediante el `UriComponentsBuilder` suministrado por Spring: añade `/api/ingredients/{id}`, expande el ID guardado y crea `ResponseEntity.created(location).body(i)`.

La URI deja de depender de `localhost` o de un puerto concreto. No se introduce un DTO porque en este reto el contrato de creación coincide con el modelo `Ingredient` y sus validaciones tienen una finalidad funcional directa.

## Flujo

Petición POST → deserializar y validar → incorporar el ingrediente al `Mono` → guardar → tomar el ingrediente persistido → construir `Location` → responder `201`. Si la validación falla → `400` sin guardar.

## Archivos principales

- `IngredientController.java`: implementa la composición de creación y la URI relativa al contexto.
- `Ingredient.java`: declara las restricciones de ID, nombre y tipo.
- `IngredientControllerTest.java`: prueba la creación válida y el rechazo de datos inválidos.

## Pruebas

La prueba válida comprueba `201`, un `Location` terminado en `/api/ingredients/PICK`, el cuerpo completo y una única llamada a `save` con los valores esperados. La prueba inválida envía ID y nombre vacíos y tipo nulo; espera `400` y verifica que el repositorio no fue invocado.
