# TC-20 — Taco del día determinista y comprobable

## Objetivo

Ofrecer `GET /api/tacos/today` con un taco recomendado, la fecha usada para elegirlo y una razón breve. La elección debe ser estable para una fecha y un catálogo dados, poder cambiar de forma predecible al avanzar el reloj y excluir diseños que ya no sean válidos o disponibles.

## Problema encontrado

El catálogo permitía buscar y consultar tacos, pero no tenía una recomendación diaria. Elegir el primer resultado dependería del orden en que MongoDB entregara los documentos. Usar la hora del sistema directamente dificultaría comprobar el cambio de día en una prueba. Además, un taco guardado podía contener ingredientes que después dejaron de estar disponibles.

## Solución implementada

La solución fue añadir `TacoOfDayService`. Recibe el repositorio, el validador de diseños de TC-18, un `Clock` inyectado y una zona horaria configurable. `Mono.defer` calcula la fecha al suscribirse. Así una misma instancia del servicio responde a la fecha vigente en cada solicitud. La zona se configura con `tacocloud.taco-of-day.zone`, inicialmente `UTC`.

Cada consulta vuelve a comprobar los tacos existentes. `concatMap` ejecuta la validación reactiva de cada diseño. Una violación de diseño excluye ese candidato. El validador resuelve los ingredientes actuales y comprueba sus reglas, incluida la disponibilidad y el stock. Luego `collectSortedList` ordena por ID, sin depender del orden físico del repositorio.

```java
return tacoRepo.findAll()
    .filter(taco -> StringUtils.hasText(taco.getId()))
    .concatMap(taco -> designValidator.requireValid(taco)
        .onErrorResume(TacoDesignException.class, error -> Mono.empty()))
    .collectSortedList(Comparator.comparing(Taco::getId))
    .flatMap(candidates -> {
      if (candidates.isEmpty()) {
        return Mono.error(new ResponseStatusException(HttpStatus.NOT_FOUND,
            "No hay tacos válidos y disponibles para recomendar."));
      }
      int index = (int) Math.floorMod(date.toEpochDay(),
          (long) candidates.size());
      return Mono.just(new Selection(candidates.get(index), date,
          "Porque hoy es " + date + " y este diseño está disponible."));
    });
```

`date.toEpochDay()` da un número reproducible para la fecha. El módulo con la cantidad de candidatos elige una posición del catálogo ya ordenado. `Math.floorMod` también produce una posición válida para fechas anteriores a 1970. Si no queda ningún candidato, la API responde HTTP 404. No se guarda ningún taco durante la consulta.

El controlador expone el resultado con el contrato `taco`, `date` y `reason`. `TacoOfDayResponse` presenta la fecha como texto ISO para que el cliente reciba un valor claro, por ejemplo `1970-01-01`.

```java
@GetMapping("/today")
public Mono<TacoOfDayResponse> tacoOfDay() {
  return tacoOfDayService.today()
      .map(selection -> new TacoOfDayResponse(
          toResponse(selection.getTaco()), selection.getDate(),
          selection.getReason()));
}
```

## Flujo

GET `/api/tacos/today` -> calcular fecha con reloj y zona -> leer tacos -> validar diseños e ingredientes actuales -> ordenar por ID -> elegir índice de la fecha -> responder taco, fecha y razón. Sin candidatos -> HTTP 404.

## Archivos principales

- `TacoOfDayService.java`: valida candidatos y realiza la elección determinista.
- `TacoOfDayConfiguration.java` y `application.yml`: definen la zona horaria de la recomendación.
- `TacoOfDayResponse.java`: define la respuesta y el formato de fecha.
- `TacoController.java`: publica la ruta y convierte el taco al contrato HTTP existente.
