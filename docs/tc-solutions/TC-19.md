# TC-19 — Buscar, filtrar, ordenar y paginar tacos

## Objetivo

Permitir explorar el catálogo por nombre, ingrediente, dieta, alérgeno excluido y picante. La respuesta debe incluir una página de resultados y datos suficientes para navegar por las demás páginas. La consulta debe ejecutarse en MongoDB y conservar un orden estable.

## Problema encontrado

El catálogo sólo tenía la ruta de tacos recientes. Usaba `findAll().take(12)` sin ordenar por fecha y no ofrecía filtros ni datos de paginación. La UI consultaba `?recent` y esperaba directamente una lista. Tampoco existían índices para buscar o ordenar tacos.

## Solución implementada

La solución fue añadir `TacoSearchRequest` con los filtros opcionales, `page`, `size` y `sort`. `TacoSearchService` comprueba los límites antes de consultar MongoDB. El tamaño máximo se configura con `tacocloud.taco-search.max-size`, cuyo valor inicial es 50. Un tamaño mayor se rechaza con HTTP 400. El sort sólo acepta `createdAt`, `name` o `id`, con dirección `asc` o `desc`. Cuando se ordena por fecha o nombre, el ID se agrega como desempate.

```java
return "id".equals(field) ? Sort.by(order, "id")
    : Sort.by(new Sort.Order(order, field),
        new Sort.Order(order, "id"));
```

El nombre se limita a 80 caracteres. La búsqueda es por prefijo y se construye con `Pattern.quote`, así los caracteres de regex enviados por el cliente se interpretan literalmente.

```java
filters.add(Criteria.where("name")
    .regex(Pattern.compile("^" + Pattern.quote(name))));
```

Los filtros se reúnen mediante `andOperator`. MongoDB recibe la intersección antes de entregar resultados. `find` aplica orden, desplazamiento y tamaño. `count` calcula el total con los mismos filtros, pero sin limitarlo a la página. Nunca se usa `findAll()` de tacos para filtrar en Java.

```java
Query countQuery = query(filters);
Query pageQuery = query(filters)
    .with(PageRequest.of(request.getPage(), request.getSize(), sort));
Mono<List<Taco>> content = mongo.find(pageQuery, Taco.class)
    .concatMap(classificationService::resolveIngredients).collectList();
return Mono.zip(content, mongo.count(countQuery, Taco.class))
    .map(result -> new PageImpl<>(result.getT1(),
        PageRequest.of(request.getPage(), request.getSize(), sort),
        result.getT2()));
```

Para dieta y picante, el servicio consulta los metadatos actuales de ingredientes. Utiliza `supportsDiet` y `effectiveSpice`, las mismas decisiones que usa la clasificación de TC-17. Después convierte los IDs elegibles en condiciones de Mongo sobre los tacos. Un taco sin metadatos válidos no recibe una etiqueta dietaria por una copia antigua de sus ingredientes. Los alérgenos excluidos tampoco deben aparecer en ninguno de sus ingredientes.

Se añadieron índices compuestos para fecha e ID, nombre e ID, e ingrediente, fecha e ID. La aplicación habilita su creación automática. La UI solicita `/api/tacos?page=0&size=12&sort=createdAt,desc` y lee `content` de la respuesta paginada.

## Flujo

Parámetros -> validar límites y sort -> consultar metadatos necesarios -> construir filtros Mongo -> buscar y contar -> resolver ingredientes actuales de la página -> responder contenido y metadata.

## Archivos principales

- `TacoSearchService.java`: valida parámetros y ejecuta la búsqueda paginada en MongoDB.
- `TacoSearchRequest.java` y `TacoSearchResponse.java`: definen entrada y salida de la búsqueda.
- `TacoController.java`: publica `GET /api/tacos` y convierte la página en respuestas del catálogo.
- `TacoClassificationService.java`: comparte la política dietaria y de picante con la búsqueda.
- `Taco.java` y `application.yml`: declaran y activan los índices, además del límite de página.
- `recents.component.ts` y `RecentTacosService.ts`: consultan la nueva ruta de catálogo.

Las pruebas de búsqueda usan MongoDB embebido y datos reales para comprobar filtros, paginación e índices. La prueba del controlador verifica el enlace de parámetros y la metadata HTTP. La prueba Angular comprueba la ruta de la UI y la lectura de `content`.

## Cambios realizados por otros TC

TC-22 introdujo la marca `published`. La búsqueda pública ahora excluye los tacos con `published=false` antes de aplicar filtros y paginación. Los tacos existentes sin esa marca siguen visibles. La intersección de filtros y el orden estable de TC-19 se mantienen.
