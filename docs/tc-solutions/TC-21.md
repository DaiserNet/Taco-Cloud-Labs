# TC-21 — Favoritos por usuario sin confiar en userId del cliente

## Objetivo

Permitir que un usuario guarde, quite y consulte sus tacos favoritos. `PUT /api/users/me/favorites/{tacoId}` y `DELETE` sobre la misma ruta deben ser idempotentes. `GET /api/users/me/favorites` debe devolver una lista paginada. Los favoritos de otra persona no deben quedar visibles ni modificables.

## Problema encontrado

El catálogo mostraba tacos recientes, pero no existía una relación persistente entre un usuario y sus favoritos. Tampoco había rutas `me` ni una forma de impedir duplicados cuando dos solicitudes intentaban guardar el mismo favorito a la vez. La UI no podía reconstruir un estado favorito después de recargarse.

## Solución implementada

La solución fue crear `Favorite` con `userId`, `tacoId` y una marca `orphaned`. Guarda sólo identificadores, no una copia del usuario ni del taco. El índice único de MongoDB protege la pareja incluso cuando llegan escrituras concurrentes.

```java
@Document(collection = "favorites")
@CompoundIndex(name = "favorite_user_taco_unique",
    def = "{'userId': 1, 'tacoId': 1}", unique = true)
public class Favorite {
  @Id private String id;
  private String userId;
  private String tacoId;
  private boolean orphaned;
}
```

`FavoriteService` obtiene el nombre del `Authentication` y busca al usuario en MongoDB para usar su ID persistente. Ninguna ruta recibe un `userId` del cliente. Antes de guardar, comprueba que el taco existe. `save` se mantiene en la cadena reactiva y `onErrorResume` convierte únicamente un `DuplicateKeyException` en éxito idempotente. El `DELETE` busca por usuario y taco. Si no encuentra nada, completa igualmente con HTTP 204.

```java
return userRepo.findByUsername(authentication.getName())
    .filter(user -> StringUtils.hasText(user.getId()))
    .switchIfEmpty(Mono.error(
        new ResponseStatusException(HttpStatus.UNAUTHORIZED)));
```

```java
return favoriteRepo.save(new Favorite(user.getId(), tacoId))
    .onErrorResume(DuplicateKeyException.class,
        error -> Mono.empty())
    .then();
```

El listado consulta sólo los favoritos del usuario autenticado con `PageRequest`, orden estable por `tacoId` e ID, y tamaño máximo configurable. Devuelve `content`, `page`, `size`, `totalElements` y `totalPages`. Si un taco fue eliminado, el servicio marca su favorito como huérfano y lo indica en la respuesta. Si el taco vuelve a existir, limpia la marca. Esto permite reconocer la referencia rota sin mostrarla como taco disponible.

```java
return mongo.updateFirst(query, Update.update("orphaned", orphaned),
    Favorite.class).then();
```

La actualización no inserta de nuevo un favorito borrado durante la consulta.

`SecurityConfig` permite únicamente `GET`, `PUT` y `DELETE` de estas rutas a `ROLE_USER`. Conserva CSRF y la denegación por defecto. En la lista reciente, Angular consulta las páginas de favoritos al iniciar y muestra si cada taco está guardado. El botón utiliza `PUT` o `DELETE` en una URL relativa, de modo que `HttpClient` envía el token CSRF de la configuración existente.

## Flujo

Usuario autenticado -> resolver usuario desde `Authentication` -> comprobar taco para `PUT` -> guardar con índice único o completar borrado -> responder 204. Para consultar: resolver usuario -> buscar su página -> comprobar tacos existentes -> marcar huérfanos -> devolver página -> reconstruir botones en la UI.

## Archivos principales

- `Favorite.java` y `FavoriteRepository.java`: definen el documento, el índice único y las consultas por usuario.
- `FavoriteService.java`: aplica identidad, idempotencia, paginación y marca de huérfanos.
- `FavoriteController.java`, `FavoriteResponse.java` y `FavoritePageResponse.java`: definen las rutas y el contrato HTTP.
- `SecurityConfig.java` y `application.yml`: limitan el acceso y configuran el tamaño máximo de página.
- `recents.component.ts` y `recents.component.html`: muestran y actualizan el estado favorito.
