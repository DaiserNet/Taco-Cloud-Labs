# TC-22 — Calificaciones y ranking de tacos

## Objetivo

Permitir que cada usuario califique un taco publicado de 1 a 5 y pueda cambiar su voto mediante `PUT /api/tacos/{id}/rating`. Publicar `GET /api/tacos/top?limit=10` con promedio, cantidad de votos y distribución por estrella. El ranking debe aplicar un mínimo configurable de votos y un desempate estable.

## Problema encontrado

El proyecto tenía búsqueda y recomendación de tacos, pero no guardaba valoraciones. Una puntuación dentro de `Taco` habría mezclado los votos de personas distintas y no habría impedido duplicados concurrentes. Tampoco existía una distinción entre taco publicado y no publicado. Por ello no se podía excluir del voto y de las lecturas públicas un diseño retirado.

## Solución implementada

La solución fue guardar cada voto en `TacoRating`, identificado por el usuario persistido y el taco. Un índice único compuesto hace que sólo pueda existir un voto por pareja, incluso si dos solicitudes llegan al mismo tiempo.

```java
@Document(collection = "tacoRatings")
@CompoundIndex(name = "rating_user_taco_unique",
    def = "{'userId': 1, 'tacoId': 1}", unique = true)
public class TacoRating {
  @Id private String id;
  private String userId;
  private String tacoId;
  private int score;
}
```

`TacoRatingService` toma el nombre del usuario de `Authentication`, busca su ID en `UserRepository` y comprueba que el taco exista y esté publicado. El cliente sólo envía `score`. `mongo.upsert` crea o actualiza el voto propio de forma atómica. Si una inserción simultánea encuentra el índice único, `updateFirst` termina actualizando la misma pareja. Nunca se cambia el voto de otro usuario.

```java
Query query = Query.query(Criteria.where("userId").is(userId)
    .and("tacoId").is(tacoId));
Update update = Update.update("score", score);
return mongo.upsert(query, update, TacoRating.class)
    .onErrorResume(DuplicateKeyException.class,
        error -> mongo.updateFirst(query, update, TacoRating.class))
    .then();
```

El ranking se calcula con una agregación en MongoDB. Hace `lookup` de los tacos existentes, excluye los no publicados, agrupa votos, calcula promedio y distribución, aplica el mínimo y ordena por promedio descendente, cantidad descendente e ID ascendente. El promedio expuesto tiene dos decimales con `HALF_UP`. La respuesta sólo contiene los datos necesarios para la UI.

```java
group("tacoId")
    .first("taco.name").as("tacoName")
    .count().as("voteCount")
    .avg("score").as("average"),
match(Criteria.where("voteCount").gte(minVotes)),
sort(Sort.by(Sort.Order.desc("average"),
    Sort.Order.desc("voteCount"), Sort.Order.asc("_id")))
```

`published` inicia en `true` para conservar el catálogo ya creado. Las lecturas públicas de búsqueda, detalle, recientes y taco del día excluyen un taco marcado con `published=false`. La UI de especiales muestra el ranking y permite votar desde el catálogo paginado. Su escritura utiliza la configuración CSRF existente. `SecurityConfig` permite votar a `ROLE_USER`, mantiene la administración del catálogo para `ROLE_ADMIN` y conserva la denegación por defecto.

## Flujo

Voto: USER autenticado con CSRF -> validar 1 a 5 -> resolver usuario y taco publicado -> insertar o actualizar su voto -> responder 204. Ranking: consultar votos y tacos en MongoDB -> agrupar -> aplicar mínimo y desempate -> devolver top N -> mostrar en la UI.

## Archivos principales

- `TacoRating.java` y `TacoRatingRepository.java`: documento de voto, índice único y acceso a datos.
- `TacoRatingService.java`: identidad, actualización propia y ranking agregado.
- `TacoRatingController.java`, `TacoRatingRequest.java` y `TacoRankingResponse.java`: rutas y contrato HTTP.
- `Taco.java`, `TacoSearchService.java`, `TacoOfDayService.java` y `TacoController.java`: publicación y lecturas públicas coherentes.
- `SecurityConfig.java` y `application.yml`: autorización y límites configurables.
- `specials.component.ts` y `specials.component.html`: ranking, catálogo y voto en Angular.
